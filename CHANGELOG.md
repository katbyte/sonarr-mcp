# Changelog

## Unreleased

Found by running the audits against a real library of 6,000 series.

### Fixed

- **Three audits did not finish on a big library.** `audit_missing_episodes` and `audit_cutoff_unmet` each read Sonarr's whole list of wanted episodes, tens or hundreds of thousands of rows, and `audit_all` waited on both. On 6,000 series they now answer in about 10 and 35 seconds. `audit_cutoff_unmet` counts files where it counted episodes, so a file holding two episodes is one.
- `audit_untracked_files` asks Sonarr why a file is not tracked only for the files it lists. Past `limit` they are counted, which is the quick part.
- `audit_server` named the oldest release Sonarr had ever installed as the one running. It now asks Sonarr which is running, and tells a Sonarr in a container to update by replacing its image.
- `audit_runtime` called a file that runs long a truncated download. Long files are now listed after the short ones, and described as what they more often are: two parts in one file, or an extended cut.
- `audit_series_settings` listed every series when most folders did not match the folder format. It now says so once, first, and names the format to set.

### Added

- **`audit_no_files`** names every series with no files at all, one finding each. No audit said so before: such a series showed as a list of missing seasons, as loose files in a folder, or not at all. It says which each is: wanted and never fetched, with nothing of it monitored so nothing ever will be, with video files in its own folder that Sonarr tracks none of, with no episode Sonarr knows of, or with nothing aired. `audit_all` counts it.
- `server_updates` marks the release that is running (`running`), apart from the ones that once were (`installed`).

## 0.2.0 (2026-10-12)

Sonarr itself can now be set up and run through the tools, not only its library: 141 tools, up from 69. Every delete waits to be confirmed, and credentials are kept out of what the tools say.

### Breaking

- **Every delete waits to be confirmed.** `series_delete`, `file_delete` and `tag_delete` change nothing without `confirm: true`; without it they answer what would be deleted. `tag_delete` now needs `--enable-delete` like the others, and `--enable-delete` brings every delete tool, the new settings ones included.
- **Every list pages the same way.** Each `_list` tool takes `limit` (default 100, at most 1000) and `offset`, and answers `total`, `offset` and `next_offset`. Lists that returned everything now return a page; `episode_list` returned 300 by default, and `history_list` and `log_list` 50. `log_list`'s `total_at_level` is now `total`.
- **`--allow-tools` adds to `--toolsets`**, where it kept only the tools in both; `--deny-tools` takes tools away. On its own it loads only the tools it names.
- `config_get` and `customformat_list` moved from the `admin` toolset to the new `settings` one.
- A tool that takes no arguments (`server_info`, `server_health`) refuses one, where it was ignored.
- **The Go client moved and was renamed throughout.** It is `sdk/sonarr`, where it was `lib/sonarr`, and is generated by [pandorest](https://github.com/katbyte/pandorest) v0.8.2, the generator the katbyte MCP servers share. Options and responses are `<Name>Options` and `<Name>Response`, the answer is `Answer`, each kind of id has its own type (`SeriesID`, `EpisodeID`, `TagID` and so on), a number among the options is a pointer so that 0 can be asked for, and errors come from `github.com/katbyte/pandorest/client`. It refuses a redirect rather than following one, so give it the address Sonarr itself answers on.

### Added

- **Sonarr's settings can be changed.** `config_edit` changes a section of the settings `config_get` shows and says what changed; `config_naming_preview` shows what a naming format would produce first. Changes to the host's settings wait for `confirm`, since they can cut the server off.
- **Indexers, download clients, notifications and import lists can be added, edited, tested and deleted.** So can delay profiles, release profiles, remote path mappings, auto tags, custom formats, metadata settings and saved filters. Sonarr tests a provider before saving it unless `force` is set. Credentials are set and never shown.
- **Quality profiles:** `profile_create`, `profile_edit` and `profile_delete`, with `qualitydefinition_list` and `qualitydefinition_edit` for the size each quality may be.
- **Running Sonarr itself:** backups (`backup_list`, `backup_create`, `backup_restore`, `backup_delete`), updates, disk space, restart and shutdown, the log files on disk, cancelling a command, and browsing folders as Sonarr sees them.
- **`audit_server`** checks Sonarr itself rather than the library: no recent backup, an update waiting, and the last day's errors in the log.
- **One change across many series:** `series_bulk_edit`, `season_bulk_monitor`, and `queue_grab` for several downloads in one call. Also `exclusion_list`, `exclusion_add`, `exclusion_remove`, `tag_rename` and `language_list`.
- **A `settings` toolset** holds the tools that set Sonarr up.
- **Text from outside is cleaned.** A release's name, a plot from TheTVDB, a download client's message or a line of the log has invisible characters taken out and is cut at 2000 characters, so nothing can be hidden in it. Paths and ids are left exactly as Sonarr holds them.
- **A client is told the house rules when it connects:** to treat answered text as data, how to name a series, how lists page, that a delete waits for `confirm`, and to start at `audit_all`.
- **A log of every change.** With `SONARR_LOG=info`, each write or delete is logged as one line with its credentials blanked. `SONARR_LOG=trace` shows every request and answer, blanked the same way.
- `file_delete` lists the episodes each file holds, and warns what Sonarr will do about them afterwards: download them again, or stop monitoring them.
- `command_list` takes a `command_id`, to follow a search or a rename that was still running when its tool answered.
- A call with an argument a tool does not take is told which arguments it does take.
- In the Go client, each command the tools queue has a method of its own and a form that waits for it to finish; `sonarr.New` takes options such as a logger; and `sonarr.DocumentVersion` says which Sonarr release the API was taken from.

### Changed

- **Audits are faster on a big library.** Series are read eight at a time: over three thousand series, reads that took twelve seconds take two.
- `audit_all` no longer fails when one audit cannot run: it names that audit under `failed` and keeps the rest.
- Every write tool tells a client whether it can replace or remove something, and whether calling it twice matters. All of them used to say they were harmless.
- A read is tried up to three times when Sonarr cannot be reached. A write is still sent once.
- A tool that fails unexpectedly answers with an error, and the session carries on.
- Over HTTP, an idle session is closed after half an hour, and stopping the server no longer waits for connected clients.
- `season_monitor` and `season_search` name the seasons a series has when asked for one it does not.
- Sonarr's log shows which version of sonarr-mcp is asking.
- The parts shared with the other katbyte MCP servers (serving, registering tools, cleaning answers, the test proxy) come from [go-kt](https://github.com/katbyte/go-kt) v0.6.4.
- The Docker image is built from Google's mirror of Docker Hub, and from Docker Hub itself when the mirror gives nothing.
- For contributors: the tests that run against a real Sonarr are all under `acceptance/` (`make testacc-sdk`, `make testacc-tools`) and now include a full journey of setting Sonarr up, auditing it, fixing it and taking it down; the helper scripts are in `.scripts/`; and the lint reads all the code.

### Fixed

- **Credentials no longer leak into answers.** `indexer_test` passed on an indexer's API key when Sonarr quoted the address it had asked. `notification_list` showed a webhook's headers, and a Discord, Slack or Apprise address, each of which is a credential. An address Sonarr quotes is now shown without its sign-in or the value of any parameter, and those settings are never shown.
- `series_add` answered before Sonarr had finished reading the show, so a season monitored straight afterwards could be unmonitored again. It now waits (`wait_seconds`, default 60).
- A search asked to return at once (`wait_seconds: -1`) still waited, for up to thirty seconds. It now answers at once.
- Several edits of one series in the same turn no longer undo each other.
- `season_monitor` did nothing when a season's own flag already matched, even though its episodes were still monitored or its series was not. It now sets those too.
- `command_list` shows what is running or waiting first, then what finished, newest first. On a busy server the first page used to show neither.
- `audit_cutoff_unmet` said to search for upgrades on a profile with upgrades off, which finds nothing. It now says to turn upgrades on first.
- An audit whose fix is a change to the settings names the tool that makes it, where it pointed at Sonarr's own pages.

## 0.1.0 (2026-09-19)

The first release: an MCP server, CLI and Go SDK for running and auditing a Sonarr library.

- **16 audits and `audit_all`**, each a sweep over the whole library for one thing that goes wrong, returning a worklist that names the tool that fixes it: episodes that aired and never arrived, files below their profile's cutoff, downloads stuck or failing, files and folders Sonarr has lost track of or never knew, a folder renamed or moved out from under it, names off the format, files recorded at the wrong quality or running the wrong length or in the wrong language, monitoring that will miss new seasons, series set up wrong, settings that do nothing, and Sonarr's own health checks.
- **69 tools in toolsets**: series, seasons, episodes and files; searching, grabbing and the queue; history and the blocklist; imports, renames, rescans and refreshes; tags, profiles, custom formats and root folders; indexers and download clients, listed and tested; tasks, commands and logs. The default `core` set is six read-only tools, about 850 tokens; `curation` loads the audits and everything that fixes what they find.
- **Deleting is opt-in.** `series_delete` and `file_delete` are only registered with `--enable-delete`, and `--read-only` registers the 43 read tools and nothing else.
- **`lib/sonarr`**: a complete Go client for Sonarr's v3 API, all 228 operations, generated from Sonarr's own OpenAPI document with the document's bugs fixed by named workarounds, each of which fails the import once Sonarr fixes its bug. The tests call 224 of the 228 against a real Sonarr; the other four restart, stop or restore it.
- **Tested against a real Sonarr 4.0.20** in Docker, with a fake indexer and a fake SABnzbd the tests drive, so searches really grab and downloads really import. The suite fails if a registered tool has no test, or if an audit can report a kind of finding the seeded library never produced and nothing explains. Sonarr's calls to TheTVDB and its own services are recorded and replayed, so the tests need no network.
- Serves MCP over stdio, or over HTTP with a bearer token (`--listen`), and ships as a container image.
